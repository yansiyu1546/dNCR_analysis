# dNCR prediction analysis: source code

This directory contains five source files covering primary model development and
validation, performance evaluation, feature-selection stability and sensitivity
analyses, SHAP explanations, and post-hoc threshold exploration.

## Files

| File | Purpose |
|---|---|
| `step_1_modeling_utils.py` | Shared configuration, random-seed generation, preprocessing, multiple imputation, Boruta selection, model fitting, calibration, threshold selection, and prediction utilities. Imported automatically; no separate execution is required. |
| `step_2_run_primary_analysis.py` | Primary nested cross-validation and final model fitting for LR, RF, XGB, ANN, and SVM. Exports fold assignments, search records, predictions, fitted pipelines, and completed datasets. |
| `step_3_evaluate_model_performance.py` | Performance and calibration tables, paired AUC comparisons, decision-curve data, and publication figures from saved predictions. |
| `step_4_analyze_stability_and_shap.py` | Boruta selection stability, selection-rule sensitivity analyses, and SHAP explanations of the locked primary model. |
| `step_5_explore_posthoc_thresholds.py` | Post-hoc exploration of development sensitivity targets of 90% and 95%, with fitted models and calibration held fixed. |

## Environment

The analysis environment uses Python 3.12.10. Package versions are specified in
`requirements.txt`. Install them in a dedicated environment:

```shell
python -m pip install -r requirements.txt
```

## Directory layout

Each entry point resolves the project root as the parent of the directory
containing its source file. Keep all five Python files together, one level below
the project root. The source directory can be named `src`, `scripts`, or another
name; the parent relationship determines the paths.

```text
project_root/
  source_directory/             # this directory
    step_1_modeling_utils.py
    step_2_run_primary_analysis.py
    step_3_evaluate_model_performance.py
    step_4_analyze_stability_and_shap.py
    step_5_explore_posthoc_thresholds.py
    requirements.txt
    README.md
  data/
    training.xlsx
    external.xlsx
  cache/
  models/
  results/
  imputations/
  figures/
  reports/
```

Input data availability is described in the manuscript's data availability
statement. Full analysis execution requires the original project inputs.

## Analysis order

File numbers describe the reading and analysis order. Step 1 is a shared module
that is imported automatically; start execution with step 2. Run the following
commands from the directory containing these Python files. Steps 3--5 use
artifacts generated by the primary analysis. Reproduction of previously
generated results requires the corresponding inputs and environment.

```shell
# 2. Primary model development and validation
python step_2_run_primary_analysis.py --jobs 6

# 3. Performance tables and figures
python step_3_evaluate_model_performance.py

# 4. Stability, selection-rule sensitivity analyses, and SHAP
python step_4_analyze_stability_and_shap.py --jobs 6

# 5. Post-hoc operating-point exploration
python step_5_explore_posthoc_thresholds.py
```

The post-hoc threshold analysis reuses the temporal external cohort and must be
reported as exploratory, rather than as an additional independent validation.

## Configuration and random seeds

`CONFIG` and `SPACES` in `step_1_modeling_utils.py` define the analysis settings and
hyperparameter search spaces. The master random seed is `20261017`. The `seed`
function deterministically derives seeds for individual folds, imputations,
Boruta repetitions, model fitting, search sampling, bootstrap sampling, and SHAP.


## Released model artifacts

The sibling `models` directory contains cleaned LR, RF, XGB, ANN, and SVM prediction
pipelines. The SVM pipeline retains observation-level support vectors for the
five selected predictors. See `../models/README.md` for details. Full analysis execution can generate patient-level intermediate
artifacts; keep those artifacts private when publishing source code.
